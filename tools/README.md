# tools ／ 作り直すための道具

データを直したあと、**画面と紙をそろえ直す**ための道具です。
順番を守らないと、画面の週割りと PDF の範囲表がずれます。

## 漢字を 足すとき

    python3 tools/add-kanji.py 暑 授 結           # 何をするかだけ出る
    python3 tools/add-kanji.py --write 暑 授 結    # 書きこむ
    python3 tools/split-data.py
    node tools/hani/alloc.js && node tools/n2plan/alloc.js
    python3 tools/build-weeks.py
    python3 tools/check-numbers.py                # 画面の数が ずれるので必ず

**インドネシア語の意味だけは 元データに無い**ので、`add-kanji.py` の `MEAN_ID` に
手で書きます。書かないと その字だけ 実習生の画面が英語になります。

**部首は 2か所から取ります。** Kanji alive（約1,235字）に無ければ、
**KanjiVG の `kvg:radical="general"`** から取り、`RAD` 表で
**いま使っている書き方に直します**。直さないと「部首でしぼる」がばらけます
（既存データは いとへんを `\ue715` で持っている。KanjiVG は `糸` を返す）。
表に無い部首が出たら、そこで止まります。**その部首を `RAD` に足してください。**

**レベルの札を増やすとき**（`--level=記録` のように）は、画面側も直します。

    kanji-data.json の levels に足す
    kanji.html   … .chip[data-lv=…] を漢字の2か所に足す／headStat／sortKanji の o ／
                   LVRANK ／ 学習状況のレベル一覧
    tools/check-numbers.py … 漢字画面の内訳の点検

**JLPTに出ない字は、N5+N4+N3 に入れないこと。**週の割り当てが重くなります。

**`kanji-strokes.json` を忘れないこと。**忘れても エラーは出ず、
その字だけ 書き順が出ないだけなので 気づけません（道具が両方に入れます）。

### N3の分は 第13〜28週だけに置く

`alloc.js` は N3の漢字・語彙・文型を **第13〜28週の16週**に配ります（第29・30週は置きません）。
第29週は模試の弱点直し、第30週は直前確認にあてるので、**新しいことをしない週**です。
画面（`shinjin/index.html`・`kanji.html`・`bunpo/index.html`）の文が この形に依っているので、
**18週に戻すと画面と食いちがいます**。`check-numbers.py` が この形を見ます。

範囲表の表紙に出る数（読める語の数・その週の漢字を使う語の割合など）は、
`gen.js` が**毎回数えて出します**。手で書いていたときに古い値のまま残っていたので変えました。

**注意**：`alloc.js` を走らせ直すと、**週の割り当てが最初から計算し直されます**。
数語を直しただけのときは、すでに通っている学習者の予定が動いてしまうので、
`plan.json` の中のその語だけを直して `build-weeks.py` を通すほうが安全です。

## 紙の教材（`kaigo/`）を直したときの順番

    # 中身を直すときは tools/kaigo/md/*.md を直す（Word は元の控え）
    python3 tools/kaigo/check-tests.py      # 問題と解答が 合っているかを 点検する
    python3 tools/kaigo/build.py            # md → PDF を作り直す
    python3 tools/check-numbers.py          # 画面の「全12点」と ファイル数を突き合わせる
    python3 tools/check-version.py          # 版が そろっているかを 点検する

**問題を足したら、`check-tests.py` が通っても 必ず目で読むこと。**
「正解が2つある」（例：「ボタンを（　）」に「かける」と「とめる」の両方）は
機械では見つかりません。書き足したとき 4件 出しました。

Word を新しくもらったときだけ、フォルダを渡して md から作り直します。

    python3 tools/kaigo/build.py /path/to/Word版

**注意**：`md` を直したあとに Word から作り直すと、直した分が消えます。
Word を渡すのは、**新しい教材が増えたとき**だけにしてください。
そのときは、解答が回の途中に入った状態に戻るので、`answers-to-back.py` を
もう一度かけてください（`--write` なしで走らせると、何をするかだけ出ます）。

## 職員用と 実習生用を 分けること

    python3 tools/check-staff-split.py    # 実習生から 職員用に たどり着けないかを 見る

答え・判定の目安・聴解の読み上げスクリプトが入ったものは、実習生が先に見ると
**テストが成立しなくなります。**職員用のものは `staff/`・`kaigo/`・`shindan/` に置き、
**実習生の入口メニューからはリンクしません。**職員はブックマークで入ります。

**これは「隠す」だけで「守る」ではありません。**このサイトは公開なので、
URLを知っていれば合言葉なしで誰でも開けます。本当に守るには、
答えの入ったファイルをサイトから外して社内の共有フォルダに置くしかありません。

## 100日コースの 直前2週を 直すとき

    python3 tools/n3-last2.py            # 何をするかだけ出る
    python3 tools/n3-last2.py --write    # 書きこむ

第13・14週に「公休」の日を足して、**N3模試 第1回・第2回**を入れます。
第14週の日曜のうしろに**直前の確認**（持ち物・行き方・前日は勉強しない）を足します。

**`n3.html` の `WEEKS` は 巨大な1行**です。手で直すと まず 壊します。
実際に この2つを やりました。

1. **属性を二重引用符で書いた**（`class="act"`）。`"v":"…"` の中なので文字列が切れ、
   **script 全体が SyntaxError で止まりました**。属性は 単引用符で書くこと。
2. **入れる場所を1つ まちがえた**。`'],"answers"'` は **days の配列を閉じる `]`** なので、
   そこに blocks を入れると「曜日の無い日」が1つでき、`d.key.replace` で画面が落ちました。
   ねらうのは その2つ手前、**最後の日の blocks を閉じる `]`** です。

どちらも **画面で開くまで気づきませんでした**（`node --check` は通ってしまいます）。
そこで道具の中に点検を入れ、**通らなければ書きこまない**ようにしました。
わざと二重引用符に戻して、止まることを確かめてあります。
**それでも、直したら必ず実ブラウザで第13・14週を開いて見ること。**

## 参考書のリストと 突き合わせるとき

    python3 tools/reference/check-ref.py           # まとめだけ
    python3 tools/reference/check-ref.py --list    # 足りないものを 全部

**市販の本のリストは、リポジトリに置かないこと。**
このリポジトリは**公開**なので、本の巻末リストをそのまま入れると
**出版社の著作物をそのまま公開する**ことになります。
一度 入れてしまい、消しました（`日本語総まとめ』巻末リスト1,292件、
『日本語の森』N3重要語彙300・N3文法50）。`.gitignore` に入れてあります。

リストは Google ドライブから落として **`/tmp/ref/`**（リポジトリの外）に置いて使います。
場所は環境変数 `OWLREF` で変えられます。**この端末の作業用の場所は消えるので、
毎回ドライブから落とし直します。**もとがドライブにあるので、それで困りません。

**このシステムの持ち主が作ったリスト**（AIに作らせたものなど）は、
`tools/reference/` に置いてかまいません。

**「無い」の数え方には気をつけること。** 最初に 170語と出しましたが、
`ご飯`と`御飯`、`答え`と`答`、`お湯`と`湯`、`支払い`と`支払` のように
**同じ語を別の書き方で書いているだけ**のものを「無い」に数えていました。
いまは ①お／ご／御 ②〜する ③送りがな（漢字2字以上の骨組みが同じ）を そろえて見ます。
**骨組みが漢字1字のものは機械では見分けられません**（「曲がる」＝データの「曲る」だが、
「曲」＝音楽は別の語。骨組みはどちらも「曲」）。目で見て確かめた分だけ
`SAME_BY_EYE` に書いてあります。

## 外部サイトへのリンクを足すとき

**このリポジトリは公開（public）です。合言葉はブラウザの中で画面を隠しているだけで、
HTMLやMarkdownに書いたことは合言葉なしで誰でも読めます。**

    python3 tools/check-secrets.py        # 鍵やパスワードが まぎれていないかを 見る

- **鍵つきURL（`?k=…`・`?token=…`）は書かない。** ログイン画面など、
  だれが見ても困らないURLだけを載せる。
- `target="_blank" rel="noopener noreferrer"` を付ける。
  `noreferrer` は、こちらのURLを相手のサイトに渡さないため。
- **リンクが生きているかは機械で見られません**（この環境は外に出られません）。
  人が時々開いて確かめてください。

一度、**「鍵つきURLは載せない」と書いた説明文の中に鍵そのものを書いてしまいました**
（公開前に気づいて消しました）。気をつけるだけでは また やるので、道具にしました。

## 道具が出した結果の扱い

**道具が「おかしい」と言った件は、必ず手で確かめてから直すこと。**
以前、`check-ui.mjs` が出した12件が全部その道具自身のまちがい（見ている場所が
ちがった）だったことがあります。
