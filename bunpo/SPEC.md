# 介護の文型（文法）学習ツール 仕様書

## 1. システム概要

日本で働くインドネシア人技能実習生（介護）向けの、日本語文型（文法）学習ウェブアプリです。同じリポジトリにある漢字・熟語アプリの姉妹アプリで、設計方針をそのまま引き継いでいます。

**主要な仕様**

| 項目 | 内容 |
|---|---|
| 対象 | JLPT N5〜N3（全レベル収録済み） |
| 収録 | 文型376項目、例文1,128、練習問題1,128 |
| 表示言語 | 日本語＋インドネシア語（英語に切替可） |
| 動作環境 | Webブラウザ（PC・スマホ・タブレット） |
| サーバー | GitHub Pages（無料・静的ホスティング） |
| 費用 | 0円、登録不要 |
| 個人情報 | 収集しない。学習記録は端末内のみ |
| 公開URL | https://owlwindkaze-ux.github.io/owltiger1021/bunpo/ |
| 合言葉 | `owltiger2026`（漢字アプリと共通） |

**設計方針**

- 外部ライブラリ・CDN・API 不使用（`index.html` 単体で完結）
- サーバー側処理なし（静的ファイルのみ）
- データ（JSON）とアプリ（HTML）を分離し、データはレベルごとに分割
- 既存の漢字アプリ（リポジトリ直下の `index.html`）には一切変更を加えない

**漢字アプリとの違い**

漢字は KANJIDIC2・KanjiVG などの公開データを機械的に取得できましたが、**文型には転用できる無償データが存在しません**。JLPTは公式の文型リストを公表しておらず、市販教材の例文には著作権があり、まして「介護現場の例文をインドネシア語訳つきで」というデータはどこにもありません。そのため本アプリの例文・練習問題は**すべて介護現場向けに書き下ろした自作データ**です。既存教材からの転載はありません。

## 2. 機能仕様（3タブ構成）

| タブ | 機能 |
|---|---|
| **①文型一覧**（Daftar Pola） | 全文型をカード表示、検索・絞り込み、タップで詳細 |
| **②練習問題**（Latihan） | 3形式の出題と自動採点、間違いだけの再挑戦 |
| **③学習状況**（Progres） | レベル別到達率、要復習リスト、記録の書き出し・消去 |

### 2.1 一覧タブ

- **検索**：文型・形・意味（インドネシア語／英語）・分類・例文（日本語・読み・訳・場面）を対象に部分一致
- **絞り込み**：レベル（すべて／N5／N4／N3）×分類（24種類）×学習状態（すべて／未学習／要復習／覚えた）
- **カード表示内容**：文型・接続の形・意味・レベル・分類・学習状態マーク
- 収録レベルが増えると、レベルの絞り込みボタンは**自動で増える**（コード修正不要）

### 2.2 詳細画面

| 欄 | 内容 |
|---|---|
| BENTUK ／ 形 | 接続の形（例：動詞て形 ＋ ください） |
| ARTI ／ 意味 | インドネシア語（言語切替で英語） |
| CATATAN ／ ポイント | インドネシア語の解説＋**日本語の解説を併記** |
| CONTOH ／ 例文 | 3件。場面タグ・日本語・ふりがな・訳 |
| 学習状態 | 「覚えた」「要復習」で登録、同ボタン再押下で取り消し |

ポイント欄の日本語併記は、学習者ではなく**指導する側が内容を点検できるようにするため**のもので、言語をENに切り替えても常に表示されます。

### 2.3 練習問題タブ

**出題設定**：レベル × 範囲（全部／未学習／要復習）× 形式（3つを個別にオン・オフ）× 問題数（10／20／全部）

**3つの出題形式**

| 形式 | 色 | 内容 | 出題数 |
|---|---|---|---|
| Isian ／ 穴埋め | 青 | 空欄に入る形を4択から選ぶ（場面判断を問う設問形式を含む） | 536 |
| Arti ／ 意味 | 橙 | 文型に対応する意味を4択から選ぶ（自動生成） | 376 |
| Susun ／ 並べ替え | 紫 | 語句を正しい順に並べる | 376 |
| **合計** | | | **1,072問** |

- 選択肢は毎回シャッフルされる（位置で覚えられない）
- 誤答の選択肢は、実習生が実際に間違えやすい活用ミスを想定して作成
- **意味マッチの誤答は他の収録文型から自動生成**されるため、項目を追加するほど選択肢が自然に増える（手作業不要）
- 並べ替えは、全ての語句を置くまで「確認」ボタンが押せない
- 採点は即時。正解＝緑、誤答＝赤で同時表示し、解説を出す
- **正解すると「覚えた」、不正解だと「要復習」に自動記録**
- 終了時に正答率を表示し、「もう一度」「間違いだけやり直す」を選べる
- キーボード操作：1〜4で選択、Enter／Spaceで次へ

### 2.4 学習状況タブ

- レベル別の到達率（覚えた数／総数）とバー表示
- 要復習の文型を一覧表示（タップで詳細へ）
- 記録の書き出し（`bunpo-progress.json`）と全消去（確認あり）

### 2.5 言語切替

画面右上の `🌐 ID / EN` で意味・例文訳をインドネシア語⇔英語に切替。UIの見出しは常にインドネシア語＋日本語の併記。設定は漢字アプリと共有され、どちらかで切り替えれば両方に反映されます。

### 2.6 合言葉による閲覧制限

- 合言葉を入れるまでデータを読み込まない
- 現在の合言葉：`owltiger2026`
- SHA-256ハッシュを `index.html` の `PASS_SHA256` に保持
- **保存キーは漢字アプリと共通**（`jlpt-kanji-gate-v1`）のため、同じ端末でどちらかに入れば、もう一方は入力不要

変更方法：
```bash
python -c "import hashlib;print(hashlib.sha256('新しい合言葉'.encode()).hexdigest())"
```

> **保護の強さ**：部外者よけの目隠しレベル。ページのソースやJSONのURLを直接開ける人には見えます。

### 2.7 自動更新（キャッシュ対策）

アプリを更新しても、利用者のブラウザが古い `index.html` を保持していると反映されません。これを自動で解決します。

1. データ（`grammar.json`）は常に最新を読む（`cache: 'no-cache'`）
2. その中の `app_version` と、表示中のアプリの `VERSION` を突き合わせる
3. **不一致なら「アプリが古い」と判断し、URLに版番号を付けて自動で読み込み直す**
4. それでも直らない場合は黄色い帯で「Ctrl+Shift+R」を案内（無限ループはしない）

利用者側の操作は不要です。フッターの「🔄 最新に更新」ボタンも、URLを変えて確実に取り直す方式です。

### 2.8 学習記録の保存仕様

- 保存先：ブラウザの `localStorage`（キー `jlpt-grammar-progress-v1`）
- 形式：`{"文型のid": "known" | "review", ...}`
- **漢字アプリの記録とは別キー**なので干渉しない
- 端末・ブラウザごとに独立、サーバーには送信されない

## 3. データ仕様

### 3.1 ファイル構成

`grammar.json` は目次で、実データはレベルごとのファイルに分かれています。

```json
{
  "name": "...", "version": "2026-07-31c", "app_version": "2026-07-31c",
  "levels": ["N5", "N4", "N3"],
  "files": ["grammar-n5.json", "grammar-n4.json", "grammar-n3.json"]
}
```

各レベルファイル：`{ "level": "N5", "count": 31, "grammar": [ …1項目ぶん… ] }`

作成中でファイルが存在しなくても、他のレベルは正常に表示されます。

### 3.2 文型1項目の構造

| キー | 型 | 必須 | 内容 | 例 |
|---|---|---|---|---|
| `id` | 文字列 | ● | 一意のID | `"n5-te-kudasai"` |
| `pattern` | 文字列 | ● | 文型 | `"〜てください"` |
| `level` | 文字列 | ● | JLPTレベル | `"N5"` |
| `category` | 文字列 | ● | 分類 | `"依頼・指示"` |
| `form` | 文字列 | ● | 接続の形 | `"動詞て形 ＋ ください"` |
| `meaning_id` | 文字列 | ● | 意味（インドネシア語） | `"tolong ~"` |
| `meaning_en` | 文字列 | ● | 意味（英語） | `"please do ~"` |
| `note_id` / `note_en` | 文字列 | ● | ポイント（尼／英） | |
| `note_ja` | 文字列 | ● | ポイント（日本語） | |
| `examples` | 配列 | ● | 例文（3件） | |
| `quiz` | 配列 | ● | 練習問題（3件） | |

**例文1件**：`ja`（日本語）／`reading`（ふりがな）／`id`（尼訳）／`en`（英訳）／`scene`（介護の場面）すべて必須

**練習問題**（2種類）

```json
{ "type": "choice", "q": "立つときは、手すりを＿＿＿。",
  "choices": ["持ってください", "持ちでください", "持ちてください", "持つでください"],
  "answer": 0, "explain_id": "…", "explain_en": "…" }

{ "type": "order", "segments": ["ここに", "お名前を", "書いて", "ください"],
  "hint_id": "Tolong tulis nama Anda di sini.", "hint_en": "Please write your name here." }
```

`choice` は空欄（`＿＿＿`）に入る語を選ぶ形式のほか、「正しいのはどれですか。」という**場面判断を問う設問形式**も使えます。`match`（意味マッチ）はデータ不要で自動生成されます。

### 3.3 データ整合性の検査

`check.py` を実行すると、以下を自動検査します。

```bash
cd bunpo && python check.py
```

1. IDの重複
2. 必須項目の欠落（`pattern` `level` `category` `form` `meaning_id` `meaning_en` `note_id` `note_ja` `examples` `quiz`）
3. 例文の必須項目（`ja` `reading` `id` `en` `scene`）
4. 選択肢がちょうど4つあるか
5. 選択肢に重複がないか
6. `answer` が選択肢の範囲内か
7. 空欄記号（`＿＿＿`）または設問文（「〜か。」）のどちらかがあるか
8. 解説（`explain_id` `explain_en`）の有無
9. 並べ替えの語句が3つ以上あるか、ヒントがあるか
10. **想定外の文字の混入**（日本語・インドネシア語・英語以外の文字）
11. **日本語の文に英単語が紛れていないか**（カタカナ語は除く）

項目10・11は、作成中に実際に混入事故（キリル文字3か所、英単語1か所）が起きたため追加した検査です。目視では発見できないため、データを追加したら必ず実行してください。不備があると終了コード1で止まります。

## 5. 使い方

### 5.1 学習者（技能実習生）向け

1. ブラウザで **https://owlwindkaze-ux.github.io/owltiger1021/bunpo/** を開く
2. 合言葉を入力（次回からは省略）
3. ホーム画面に追加（iPhone：共有→ホーム画面に追加／Android：メニュー→ホーム画面に追加）

**おすすめの学習手順**

- **一覧タブ**：レベルをN5にして眺め、気になる文型をタップ → 意味・ポイント・介護の例文を確認
- **練習タブ**：「N5・未学習・穴埋めと意味だけ・10問」から開始。慣れたら並べ替えを追加
- 間違えた文型は自動で「要復習」に入る。翌日は範囲を「要復習」にして復習
- **学習状況タブ**：到達率を確認

### 5.2 管理者（導入・運用担当）向け

**日常運用**：不要（静的サイトのため無停止・無保守）

**手元で動かして確認・編集**：
```bash
git clone https://github.com/owlwindkaze-ux/owltiger1021.git
cd owltiger1021
git checkout claude/japanese-n3-kanji-AaKYe
python -m http.server 8000
# ブラウザで http://localhost:8000/bunpo/ を開く
```

> ファイルをダブルクリックで直接開くとJSONを読み込めません。ローカルサーバー経由で開いてください。

**修正を公開サイトに反映**：
```bash
cd bunpo && python check.py      # 必ず先に検査する
cd .. && git add -A
git commit -m "修正内容の説明"
git push origin claude/japanese-n3-kanji-AaKYe
# 1〜2分でGitHub Pagesに反映される
```

### 5.3 文型を1項目だけ追加・修正する

該当レベルのファイル（例：`grammar-n5.json`）の `grammar` 配列に、3.2の形式で1件追加し、`count` を更新します。追加後は必ず `python check.py` を実行してください。

**アプリ側の修正は不要です。** レベルの絞り込みボタン、分類の選択肢、出題数はすべてデータから自動生成されます。新しいレベルを追加する場合のみ、`grammar.json` の `levels` と `files` に1行足します。

### 5.4 アプリ本体（`index.html`）を修正したとき

修正後、**必ず2か所の版を同じ値に更新**してください。

1. `index.html` の `const VERSION = '…'`
2. `grammar.json` の `"app_version": "…"`

これが一致していないと、利用者のアプリが「古い」と判断して読み込み直しを繰り返そうとします（1回で止まる仕組みは入っていますが、黄色い警告帯が出ます）。

| 対応ブラウザ | Chrome・Safari・Edge・Firefox の最新版 |
| 合言葉の強度 | 部外者よけの目隠しレベル |
| 練習問題のふりがな | 未対応（例文にはふりがなあり） |
| 音声 | 未対応 |
| 対応言語 | インドネシア語と英語のみ。画面の見出しは常にインドネシア語＋日本語（言語を増やす場合は、HTMLに直書きしている約160か所のラベルを翻訳表に切り出す作業が必要） |

## 8. データの出典と品質について

- 文型の項目名は、広く流通している一般的な文型の名称を用いています。JLPTは公式の文型リストを公表していないため、レベル区分は教材によって境界が異なる場合があります。
- **例文・練習問題・解説はすべて介護現場向けの書き下ろし**です。既存教材からの転載はありません。
- インドネシア語訳・英訳はAIで作成しました。**漢字アプリで実施したような第三者による抽出検査は、まだ行っていません。** 実際に使う実習生に確認してもらい、不自然な箇所を修正することを強く推奨します。
- 敬語の扱い（「〜てあげます」「使役」を利用者さんに使わない、など）は、介護現場の慣行に基づいて注意書きを付けています。施設の方針と異なる場合は修正してください。
