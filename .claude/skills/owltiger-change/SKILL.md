# owltiger1021 を 変えるときの手順

**ここに書いてあるのは、この3か月で 実際に やらかしたことだけ**である。
一般的な心がけは 書かない。**守ったかどうかを 確かめられること**だけを書く。

実習生2人が 毎日 使っている。**まちがいは そのまま 相手に届く。**

| | |
|---|---|

| `MANUAL.md` | 使う側の説明書。**数字が 書いてある**ので、データを変えたら ここも変わる |

## 1. データを直したら、分け直す

語彙（`vocab-data.json`）を 直したら **必ず**：

```
python3 tools/split-data.py
```

レベル別ファイル（`vocab-n*.json`）と 目次（`vocab.json`）を 作り直す。
**忘れると 画面と データが 食い違う。**

---

## 2. 検査を 走らせる

```
for f in tools/check-*.py; do echo "--- $f"; python3 "$f" || true; done
```

**18本ある**（Python 17本・ブラウザ1本）。Python の分は **3秒**で終わる。
毎回 全部 走らせる。「関係ないから」で 飛ばさない。

> **push すると、GitHub でも Python 17本が 自動で 走る**
> （`.github/workflows/check.yml`）。GitHub の画面に 緑か赤の印が 出る。
> **だからといって 手元で 走らせないのは だめ。**赤を 持ち主に 見せることになる。
> 自動の分は 「忘れたときの 網」であって、手元の検査の 代わりではない。

実ブラウザの検査は 別：

```
(setsid python3 -m http.server 8899 >/dev/null 2>&1 < /dev/null &)
node tools/check-ui.mjs
```

**15分ほどかかる**ので、裏で走らせて ほかの作業を進めてよい。
ただし **結果を見る前に コミットを main へ出さない。**

---

## 3. ★ 画面を 自分で 触る

検査が 0件でも、**画面を開いて 触る**。読むだけでは 足りない。

実際に あったこと：

- **問題文そのものが 無かった**。AIは「週テスト50本、完成しました」と報告していた
- **戻るボタンが 無かった**。使えば1秒、プログラムを読んでも 分からない
- **押しても 何も起きないリンクが 46週ぶん**
- **太字のつもりが、星印が そのまま 出ていた**（週テスト53本・語彙4語）

> **報告を読むのではなく、ものを見る。**

---

## 4. ★★ 直したら、同じ形が ほかに ないか 探す

**これを 3回 破った。**この手順書で いちばん 大事なところ。

| 直したもの | 広げ忘れた先 | 結果 |
|---|---|---|
| ★の問に 正解のかたよりの検査（z76） | 100日コース | **ドリル420問の 75.5%が 1番**だった（z81・持ち主が発見） |
| 週テストの `lead` の `**`（z74②） | 語彙の `caution` | **同じ星印を また出した**（z82①） |
| 敬語の表の 例文の重なり | 自動詞・他動詞の表 | 自分で気づいて 直した（z66） |

直したら、**必ず声に出して聞く**：

```
同じ作り方を している所が、ほかに ありませんか。
同じ検査を 当てられる所が、ほかに ありませんか。
```

## 5. ★★★ main にマージしたあと、もう一度 全部の検査

**10月25日、「検査15本すべて0件」と報告した。翌日 main は 落ちていた。**
枝の上でしか 確かめていなかった。

```
git fetch origin main
git checkout -B tmpmain origin/main
git merge --no-ff <枝>
# ← ここで もう一度 18本 全部
git push origin tmpmain:main
```

**「0件でした」と言うときは、どこで走らせたかを 必ず添える。**

> **2026-11-24a から、ここは 機械も 見ている。**
> main へ push したあと、GitHub で 17本が 走る。落ちていれば 赤が出る。
> ただし 走るのは **push した あと**である。**壊れた main を 止めてはくれない。**
> 止めるのは、ここで 自分で 走らせる 一回だけ。

## 6. 書きかえてはいけないもの

**すでにある週テスト（`moshi/w-*.json`）は 作り直さない。**

種は固定してあるが、**もとの語彙・漢字のデータが動くと 選ばれる語がずれる**。
実習生が すでに受けた週の問題が変われば、**前に取った点と くらべられない。**

**先に サーバーを立てる。**立てないと `ERR_CONNECTION_REFUSED` で 止まる
（漢字・語彙の問題は `kanji.html` を 開いて その中の関数を 呼んで 作るため）。

```
(setsid python3 -m http.server 8777 >/dev/null 2>&1 < /dev/null &)
node tools/weektest.mjs n2 all     # すでにある週は そのまま
FORCE=1 node tools/weektest.mjs n2 25   # 作り直すときは 週を名指し
```

`FORCE=1` は `all` では 効かない。**直した その日に 自分で 迂回した**ので そうした（z75②）。


## 10. 終わりに すること

```
① SPEC.md に 記録を書く（何を直したか・なぜ・どう確かめたか）
② version.json と 各ページの PAGE_VER を そろえる（check-version.py）
③ PDF を 作り直す
     python3.13 tools/pdf/md2html.py SPEC.md /tmp/out/spec.html "仕様書"
     node tools/pdf/mkpdf.mjs /tmp/out/spec.html <絶対パス>/仕様書.pdf "owltiger1021 仕様書"
④ コミット → 枝へ push → main へマージ → **5. の再検査** → push
⑤ 必要なPDFを 画面から 直接 渡す（持ち主の決めごと）
```

## この手順書の 限界

**これは 検査ではない。読んで 従わなければ 効かない。**

機械で 確かめられることは、**手順書ではなく 検査にする**。

**5.（マージ後の再検査）は 機械に 移した**（2026-11-24a・GitHub Actions）。
いま 手順書だけで 守っているのは **4.（直したら 同じ形を 探す）** である。
これは 3回 破った。機械に できないので、ここに 書いてある。

機械に 渡していないもの：

| | なぜ |
|---|---|
| ブラウザの検査（15分） | 重い。**画面を 自分で 触ることは 人の 仕事**（3.） |
| 日本語が よいかどうか | 「青black」は 捕まるが、「読みにくい説明文」は 捕まらない |
| 4.（同じ形を 探す） | **機械に できない** |
